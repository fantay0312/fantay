# Content discipline craft

Brand-agnostic rules about the content you author into a design (slides, pages, dashboards, mockups), as opposed to the chrome around it. They apply to every skill that opts in. Adapted from the shared content rules of Anthropic's Artifact types (see `skills/claude-design-system/NOTICE.md`). None of them overrides a design system's token or component rule.

- **No filler.** Never pad a design with placeholder text, dummy sections or informational material just to fill space. Every element earns its place. If a section feels empty, solve it with layout and composition, not by inventing content. Avoid data slop: unnecessary numbers, icons or stats that are not useful. Less is more; bias toward minimalism.
- **Ask before adding material.** If extra sections, pages, copy or content would improve the design, ask the user first through a `<question-form>` (or propose it in one line at the end) rather than adding it unilaterally. The user knows the audience and goals better than you do.
- **Targeted changes stay targeted.** When the user asks for a small change (some text, a color, one element), change only that. Leave all other layout, spacing, margins, fonts, sizes, positions, colors and content exactly as they are, and do not "improve" parts you were not asked to touch. A redesign, a new direction or a from-scratch request is different: make the substantial changes asked for. If a broader change would help, finish what was asked and suggest the rest.
- **Follow the existing visual vocabulary.** When adding to an existing UI or document, understand its vocabulary first and match copywriting style, color palette, tone, hover and click states, animation, shadow, card and layout patterns, and density.
- **Avoid AI slop tropes.** Aggressive gradient backgrounds, emoji (unless the brand or design system uses them) and rounded containers with a colored left-border accent are the usual offenders. Interface chrome never uses emoji as icons, unconditionally.
- **Recreate from source, not from memory or screenshots.** When asked to recreate a UI or design whose source you can reach (a repo, a pasted file, an attached design system), read the real source and build from it: read the components and styles, copy the assets the design actually uses, and copy exact numeric values (paddings, radii, font sizes, line-heights) instead of rounding them to a 4 or 8px grid or a framework default. Treat screenshots as high-level guidance only when source is available.
- **Never invent facts.** No made-up statistics, quotes, customer names or logos. A missing value is a short honest placeholder in brackets, listed in your reply. Data you wrote yourself is labeled as sample data on the page.
- **Do not recreate copyrighted designs.** Do not reproduce a company's distinctive UI patterns, proprietary command structures or branded visual elements unless the user says they work at that company (ask when it is unclear). Understand what the user wants to build and help create an original design instead.
- **Keep the user's words.** Existing copy, names and terminology are data to keep. Rewrite only when asked, and say what you changed.
